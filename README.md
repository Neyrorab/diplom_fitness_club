# ИС "Фитнес-клуб"

Веб-приложение на Django для учета клиентов, тренеров, абонементов, тренировочных планов, дневника питания, прогресса и отчетов фитнес-клуба.

## Запуск

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

## ИИ-анализ управления

В разделе администратора **Дашборды** есть блок **ИИ-анализ**. Перед запуском администратор может выбрать агрегатор в интерфейсе. По умолчанию агрегатор задается через `AI_PROVIDER`:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Ключ можно указать в файле `.env` в корне проекта:

```text
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=anthropic/claude-sonnet-4.6
OPENROUTER_FAST_MODEL=google/gemini-3.5-flash
OPENROUTER_BALANCED_MODEL=anthropic/claude-sonnet-4.6
OPENROUTER_SMART_MODEL=openai/gpt-5.5-pro
```

Основная модель GPTunnel задается через `GPTUNNEL_MODEL`, а `GPTUNNEL_FALLBACK_MODELS` задает запасные модели, которые приложение попробует по очереди при сбое основной. Запуск анализа создает фоновое задание: его можно дождаться на дашборде или вернуться к результату позже.

В каждом ИИ-блоке администратор, тренер и клиент могут выбрать профиль модели:

- **Быстрая** — минимальная задержка;
- **Оптимальная** — баланс скорости и качества;
- **Умная** — самая тяжелая модель, обычно медленнее.

Конкретные модели для профилей можно переопределить в `.env`: `GPTUNNEL_FAST_MODEL`, `GPTUNNEL_BALANCED_MODEL`, `GPTUNNEL_SMART_MODEL`, `OPENROUTER_FAST_MODEL`, `OPENROUTER_BALANCED_MODEL`, `OPENROUTER_SMART_MODEL`, `ZAI_FAST_MODEL`, `ZAI_BALANCED_MODEL`, `ZAI_SMART_MODEL`.

Текущие пресеты по умолчанию:

| Провайдер | Быстрая | Оптимальная | Умная |
| --- | --- | --- | --- |
| OpenRouter | `google/gemini-3.5-flash` | `anthropic/claude-sonnet-4.6` | `openai/gpt-5.5-pro` |
| Z.ai | `glm-5-turbo` | `glm-5` | `glm-5.1` |
| GPTunnel | `gpt-4o-mini` | `gpt-4o` | `gpt-4-turbo` |

Для возврата к OpenRouter можно поставить `AI_PROVIDER=openrouter`, заполнить `OPENROUTER_API_KEY` и указать `OPENROUTER_MODEL`. Для возврата к Z.ai можно поставить `AI_PROVIDER=zai` и заполнить `ZAI_API_KEY`. Разрешенные Z.ai-модели задаются через `ZAI_ALLOWED_MODELS`; по умолчанию доступны `glm-5.1`, `glm-5`, `glm-5-turbo`, `glm-4.7`, `glm-4.7-flash` и `glm-4.5-flash`.

Для проверки ответа ИИ на разных состояниях клуба можно заменить клиентские демо-данные одним сценарием:

```powershell
.\.venv\Scripts\python.exe manage.py seed_ai_scenario --scenario retention_crisis
```

Доступные сценарии: `retention_crisis`, `healthy_growth`, `renewal_wave`, `trainer_imbalance`. Команда очищает прошлые клиентские данные и старые результаты ИИ-анализа, затем создает новый сценарий поверх демо-базы.

## Реализовано

- авторизация и разграничение доступа по ролям;
- карточки клиентов и профили тренеров;
- учет абонементов и клиентов с риском ухода;
- справочники упражнений и продуктов;
- тренировочные планы, дни, упражнения и отметка выполнения;
- дневник питания с расчетом калорий и БЖУ;
- нормы питания, записи прогресса и график веса;
- отчеты и админ-дашборды по активности, риску ухода, загрузке тренеров, абонементам и целям клиентов;
- фоновый ИИ-анализ управленческих метрик администратора через GPTunnel, OpenRouter или Z.ai с рекомендациями по развитию клуба;
- персональный кабинет клиента с физическими показателями и графиками веса/замеров;
- отзывы клиентов о фитнес-клубе с оценкой, публикацией и просмотром общей ленты;
- локальная ИИ-система рекомендаций на основе цели, прогресса, тренировок, питания и абонемента;
- команда наполнения демонстрационными данными `seed_demo`.
