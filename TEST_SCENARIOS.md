# Бизнес-сценарии проверки ИС "Фитнес-клуб"

Документ нужен, чтобы спокойно проверить сайт перед демонстрацией. Все шаги написаны максимально простым языком: что открыть, куда нажать, что должно получиться.

## Подготовка

1. Запустить сервер:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

2. Открыть сайт в браузере:

```text
http://127.0.0.1:8000/login/
```

3. Использовать демо-пользователей:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `admin12345` |
| Тренер | `trainer1` | `trainer12345` |
| Клиент | `client1` | `client12345` |

Если данные пропали, выполнить:

```powershell
.\.venv\Scripts\python.exe manage.py seed_demo
```

# 1. Сценарии администратора

Администратор отвечает за клиентов, тренеров, абонементы, справочники и отчеты.

## A1. Простой сценарий: вход администратора

Цель: проверить, что администратор может войти в систему.

Шаги:

1. Открыть страницу входа.
2. В поле **Логин** ввести `admin`.
3. В поле **Пароль** ввести `admin12345`.
4. Нажать кнопку **Войти**.

Ожидаемый результат:

- открывается кабинет администратора;
- слева видны разделы **Кабинет**, **Отзывы**, **Клиенты**, **Упражнения**, **Продукты**, **Отчеты**, **Дашборды**, **Тренеры**;
- вверху есть кнопка **Добавить клиента**.

## A2. Простой сценарий: просмотр списка клиентов

Цель: проверить, что администратор видит клиентскую базу.

Шаги:

1. В левом меню нажать **Клиенты**.
2. Посмотреть таблицу клиентов.
3. Найти строку с клиентом **Ирина Соколова**.
4. Нажать на имя клиента.

Ожидаемый результат:

- открывается карточка клиента;
- видны блоки **Профиль**, **Абонемент**, **Тренировки**, **Питание**, **Прогресс**, **ИИ-рекомендации**, **Комментарии**.

## A3. Простой сценарий: поиск клиента

Цель: проверить поиск по клиентам.

Шаги:

1. В левом меню нажать **Клиенты**.
2. В поле поиска ввести `Ирина`.
3. Нажать кнопку **Найти**.

Ожидаемый результат:

- в таблице остается клиент **Ирина Соколова**;
- лишние клиенты скрываются.

## A4. Средний сценарий: фильтр клиентов с низкой активностью

Цель: проверить отчетность по клиентам, которые требуют внимания.

Шаги:

1. В левом меню нажать **Клиенты**.
2. В выпадающем списке **Любая активность** выбрать **Низкая активность**.
3. Нажать **Найти**.
4. Открыть любого клиента из найденных.

Ожидаемый результат:

- страница не выдает ошибку;
- показываются клиенты, у которых давно не было тренировок;
- карточка выбранного клиента открывается.

## A5. Средний сценарий: создание нового клиента

Цель: проверить регистрацию клиента администратором.

Шаги:

1. В левом меню нажать **Клиенты**.
2. Нажать кнопку **Добавить клиента**.
3. Заполнить поля:
   - **Логин**: `testclient`
   - **Пароль**: `testclient12345`
   - **Email**: `testclient@mail.ru`
   - **ФИО**: `Тестовый Клиент`
   - **Телефон**: `+7 900 000-00-00`
   - **Цель**: выбрать любую цель
   - **Тренер**: выбрать тренера
   - **Статус**: выбрать **Активен**
4. Нажать **Сохранить**.

Ожидаемый результат:

- создается новый клиент;
- открывается карточка клиента;
- клиент появляется в списке **Клиенты**.

## A6. Средний сценарий: оформление абонемента

Цель: проверить учет абонементов.

Шаги:

1. Открыть раздел **Клиенты**.
2. Нажать на имя любого клиента.
3. Найти блок **Абонемент**.
4. Нажать кнопку **Добавить**.
5. Заполнить:
   - **Тип абонемента**: `Пробный абонемент`
   - **Дата начала**: сегодняшняя дата
   - **Дата окончания**: дата через месяц
   - **Всего посещений**: `12`
   - **Осталось посещений**: `12`
   - **Статус**: **Активен**
6. Нажать **Сохранить**.

Ожидаемый результат:

- абонемент появляется в карточке клиента;
- указаны даты, количество посещений и статус.

## A7. Средний сценарий: создание тренера

Цель: проверить управление тренерами.

Шаги:

1. В левом меню нажать **Тренеры**.
2. Нажать **Добавить тренера**.
3. Заполнить:
   - **Логин**: `testtrainer`
   - **Пароль**: `testtrainer12345`
   - **Email**: `testtrainer@mail.ru`
   - **ФИО**: `Тестовый Тренер`
   - **Телефон**: `+7 900 111-11-11`
   - **Специализация**: `Силовая подготовка`
   - **Стаж, лет**: `3`
   - **Статус**: **Активен**
4. Нажать **Сохранить**.

Ожидаемый результат:

- тренер появляется в списке тренеров;
- в таблице видно количество клиентов у тренера.

## A8. Сложный сценарий: анализ бизнеса через дашборды

Цель: проверить управленческую аналитику.

Шаги:

1. В левом меню нажать **Дашборды**.
2. Посмотреть верхние показатели:
   - клиентов в базе;
   - тренировок за 30 дней;
   - среднее выполнение планов;
   - клиентов в зоне риска.
3. Посмотреть график **Активность клуба по неделям**.
4. Посмотреть график **Цели клиентов**.
5. Посмотреть график **Статусы абонементов**.
6. Найти блок **Клиенты для контакта**.
7. В блоке **ИИ-анализ управления** выбрать агрегатор ИИ и нажать **Сформировать рекомендации**.
8. Убедиться, что появился статус фонового анализа.
9. Пока анализ выполняется, открыть другой раздел и вернуться к **Дашбордам**.
10. Нажать **Открыть список**.

Ожидаемый результат:

- если задан `OPENROUTER_API_KEY`, анализ продолжает выполняться после ухода со страницы, затем появляется вывод ИИ, приоритетные действия, риски и план на 7 дней;
- если ключ не задан, система показывает понятное сообщение о необходимости указать `OPENROUTER_API_KEY`;
- открывается список клиентов с низкой активностью;
- руководитель понимает, с кем нужно связаться;
- графики не ломаются и не выходят за границы блоков.

## A9. Сложный сценарий: проверка отчетов

Цель: проверить аналитические отчеты.

Шаги:

1. В левом меню нажать **Отчеты**.
2. Проверить блок **Активные клиенты**.
3. Проверить блок **Клиенты с риском ухода**.
4. Проверить блок **Загрузка тренеров**.
5. Проверить блок **Популярные цели**.

Ожидаемый результат:

- отчеты отображают реальные данные;
- клиенты и тренеры кликабельны или понятны по таблицам;
- администратор видит общую картину клуба.

# 2. Сценарии тренера

Тренер работает со своими клиентами: смотрит прогресс, назначает планы, анализирует питание и оставляет комментарии.

## T1. Простой сценарий: вход тренера

Цель: проверить кабинет тренера.

Шаги:

1. На странице входа ввести логин `trainer1`.
2. Ввести пароль `trainer12345`.
3. Нажать **Войти**.

Ожидаемый результат:

- открывается кабинет тренера;
- слева видны разделы **Кабинет**, **Отзывы**, **Клиенты**, **Упражнения**, **Продукты**, **Отчеты**;
- тренер не видит раздел **Тренеры**, потому что это раздел администратора.

## T2. Простой сценарий: просмотр своих клиентов

Цель: проверить, что тренер видит закрепленных клиентов.

Шаги:

1. В левом меню нажать **Клиенты**.
2. Посмотреть список клиентов.
3. Нажать на клиента **Ирина Соколова**.

Ожидаемый результат:

- открывается карточка клиента;
- тренер видит профиль, тренировки, питание, прогресс, ИИ-рекомендации и комментарии.

## T3. Средний сценарий: добавление упражнения в справочник

Цель: проверить справочник упражнений.

Шаги:

1. В левом меню нажать **Упражнения**.
2. В правом блоке **Добавить** заполнить:
   - **Название**: `Тестовое упражнение`
   - **Группа мышц**: `Кор`
   - **Тип упражнения**: `Функциональное`
   - **Описание техники**: `Выполнять плавно, без рывков`
3. Нажать **Сохранить**.

Ожидаемый результат:

- упражнение появляется в таблице упражнений;
- его можно использовать в тренировочном плане.

## T4. Средний сценарий: создание тренировочного плана клиенту

Цель: проверить работу тренера с планами.

Шаги:

1. В левом меню нажать **Клиенты**.
2. Открыть клиента **Ирина Соколова**.
3. Вверху карточки нажать **Новый план**.
4. Заполнить:
   - **Название**: `План проверки`
   - **Цель**: выбрать цель клиента
   - **Описание**: `План создан для проверки системы`
   - **Дата начала**: сегодняшняя дата
   - **Статус**: **Активен**
5. В поле **Шаблон** можно выбрать готовый шаблон или оставить пустым.
6. Нажать **Сохранить**.

Ожидаемый результат:

- открывается страница тренировочного плана;
- в плане есть тренировочный день;
- план доступен клиенту.

## T5. Средний сценарий: добавление упражнения в тренировочный день

Цель: проверить детализацию плана.

Шаги:

1. Открыть созданный тренировочный план.
2. Найти тренировочный день.
3. Нажать раскрывающийся блок **Добавить упражнение**.
4. Заполнить:
   - **Упражнение**: выбрать упражнение из списка
   - **Подходы**: `3`
   - **Повторения**: `12`
   - **Рекомендуемый вес**: `10`
   - **Отдых, сек**: `60`
   - **Комментарий**: `Следить за техникой`
   - **Порядок**: `1`
5. Нажать **Сохранить**.

Ожидаемый результат:

- упражнение появляется в таблице тренировочного дня;
- клиент увидит его в своем плане.

## T6. Средний сценарий: назначение нормы питания

Цель: проверить питание и контроль БЖУ.

Шаги:

1. Открыть карточку клиента.
2. Найти блок **Питание**.
3. Нажать кнопку **Норма**.
4. Заполнить:
   - **Ккал**: `2000`
   - **Белки**: `120`
   - **Жиры**: `70`
   - **Углеводы**: `220`
   - **Дата начала**: сегодняшняя дата
5. Нажать **Сохранить**.

Ожидаемый результат:

- в карточке клиента отображается дневная норма;
- система сможет сравнивать фактическое питание с нормой.

## T7. Средний сценарий: комментарий тренера клиенту

Цель: проверить обратную связь.

Шаги:

1. Открыть карточку клиента.
2. Найти блок **Комментарии**.
3. Нажать **Добавить**.
4. Выбрать раздел, например **Прогресс**.
5. В поле комментария написать: `Хорошая динамика, продолжаем текущий режим.`
6. Нажать **Сохранить**.

Ожидаемый результат:

- комментарий появляется в карточке клиента;
- клиент видит комментарий в личном кабинете.

## T8. Сложный сценарий: анализ клиента через ИИ-рекомендации

Цель: проверить рекомендательную систему.

Шаги:

1. Открыть раздел **Клиенты**.
2. Открыть клиента **Ирина Соколова**.
3. Найти блок **ИИ-рекомендации**.
4. Нажать **Открыть полностью**.
5. Посмотреть:
   - индекс сопровождения;
   - ключевые сигналы;
   - список рекомендаций;
   - причины рекомендаций;
   - что нужно сделать.

Ожидаемый результат:

- система дает понятные рекомендации;
- тренер видит, почему система предложила именно такие действия;
- рекомендации связаны с тренировками, питанием, прогрессом или абонементом.

## T9. Сложный сценарий: проверка ограничения доступа тренера

Цель: убедиться, что тренер не видит чужих клиентов.

Шаги:

1. Войти как `trainer1`.
2. Открыть раздел **Клиенты**.
3. Убедиться, что отображаются только клиенты этого тренера.
4. Попробовать вручную открыть карточку клиента другого тренера, если известен адрес.

Ожидаемый результат:

- тренер не должен видеть чужих клиентов;
- при попытке открыть чужую карточку система должна запретить доступ.

# 3. Сценарии клиента

Клиент смотрит свой план, отмечает тренировки, ведет питание, добавляет прогресс и читает рекомендации.

## C1. Простой сценарий: вход клиента

Цель: проверить личный кабинет клиента.

Шаги:

1. На странице входа ввести логин `client1`.
2. Ввести пароль `client12345`.
3. Нажать **Войти**.

Ожидаемый результат:

- открывается кабинет клиента;
- слева видны разделы **Кабинет**, **Отзывы**, **Профиль**, **Питание**, **Прогресс**, **ИИ-рекомендации**;
- клиент не видит административные разделы **Тренеры** и **Дашборды**.

## C2. Простой сценарий: просмотр физических показателей

Цель: проверить персональный верхний блок клиента.

Шаги:

1. Войти как клиент.
2. Открыть **Кабинет**.
3. Посмотреть верхние карточки:
   - текущий вес;
   - ИМТ;
   - талия;
   - бедра.
4. Посмотреть графики **Динамика веса** и **Замеры тела**.

Ожидаемый результат:

- клиент видит не общую статистику клуба, а свои показатели;
- графики отображаются без обрезки.

## C3. Простой сценарий: добавление отзыва о клубе

Цель: проверить, что клиент может оставить отзыв о фитнес-клубе.

Шаги:

1. Войти как клиент.
2. В левом меню нажать **Отзывы**.
3. В блоке **Оставить отзыв** выбрать оценку.
4. Заполнить поля **Заголовок** и **Текст отзыва**.
5. Нажать **Опубликовать**.

Ожидаемый результат:

- отзыв появляется в ленте отзывов;
- счетчики средней оценки и опубликованных отзывов обновляются;
- тренер и администратор могут просмотреть отзыв в разделе **Отзывы**.

## C4. Простой сценарий: просмотр профиля

Цель: проверить карточку клиента.

Шаги:

1. В левом меню нажать **Профиль**.
2. Посмотреть блок **Профиль**.
3. Проверить цель, тренера, рост, дату рождения и последнюю тренировку.

Ожидаемый результат:

- клиент видит только свою карточку;
- чужие данные не отображаются.

## C5. Средний сценарий: просмотр тренировочного плана

Цель: проверить назначенный план.

Шаги:

1. В кабинете клиента найти блок **Текущий план**.
2. Нажать **Открыть**.
3. Посмотреть тренировочные дни.
4. Посмотреть упражнения, подходы, повторения, вес и отдых.

Ожидаемый результат:

- клиент видит свой план;
- клиент не может редактировать план;
- рядом с тренировочным днем есть кнопка **Выполнить**.

## C6. Средний сценарий: выполнение тренировки

Цель: проверить фиксацию фактической тренировки.

Шаги:

1. Открыть тренировочный план.
2. Найти тренировочный день.
3. Нажать кнопку **Выполнить**.
4. В поле **Самочувствие** написать `Хорошо`.
5. Для упражнений оставить галочку **Выполнено**.
6. При необходимости изменить фактический вес, подходы или повторы.
7. Нажать **Сохранить тренировку**.

Ожидаемый результат:

- тренировка сохраняется;
- клиент возвращается в карточку;
- тренер видит выполнение в истории тренировок.

## C7. Средний сценарий: добавление питания

Цель: проверить дневник питания.

Шаги:

1. В левом меню нажать **Питание**.
2. Выбрать дату.
3. В блоке **Добавить продукт** заполнить:
   - **Дата**: нужная дата
   - **Прием пищи**: например **Завтрак**
   - **Продукт**: выбрать продукт из списка
   - **Вес, г**: `150`
4. Нажать **Добавить**.

Ожидаемый результат:

- продукт появляется в выбранном приеме пищи;
- калории, белки, жиры и углеводы пересчитываются;
- в верхнем блоке меняется итог за день.

## C8. Средний сценарий: добавление своего блюда

Цель: проверить ручной ввод продукта, которого нет в справочнике.

Шаги:

1. Открыть **Питание**.
2. В поле **Продукт** ничего не выбирать.
3. В поле **Свое блюдо** написать `Домашний салат`.
4. Заполнить:
   - **Вес, г**: `200`
   - **Ккал**: `250`
   - **Белки**: `8`
   - **Жиры**: `14`
   - **Углеводы**: `20`
5. Нажать **Добавить**.

Ожидаемый результат:

- блюдо добавляется в дневник;
- итоговые калории и БЖУ обновляются.

## C9. Средний сценарий: добавление прогресса

Цель: проверить контроль веса и замеров.

Шаги:

1. В левом меню нажать **Прогресс**.
2. В правом блоке **Новая запись** заполнить:
   - **Дата**: сегодняшняя дата
   - **Вес**: например `79.8`
   - **Талия**: например `78`
   - **Грудь**: например `94`
   - **Бедра**: например `99`
   - **Комментарий**: `Контрольный замер`
3. Нажать **Сохранить**.

Ожидаемый результат:

- запись появляется в таблице;
- график веса обновляется;
- верхние показатели в кабинете клиента меняются.

## C10. Сложный сценарий: просмотр ИИ-рекомендаций

Цель: проверить рекомендации на основе данных клиента.

Шаги:

1. В левом меню нажать **ИИ-рекомендации**.
2. Посмотреть большой показатель **индекс сопровождения**.
3. Посмотреть блок **Ключевые сигналы**.
4. Ниже прочитать рекомендации.
5. У каждой рекомендации посмотреть:
   - категорию;
   - приоритет;
   - почему появилась рекомендация;
   - что нужно сделать.

Ожидаемый результат:

- рекомендации отображаются понятно;
- клиент понимает, что делать дальше;
- советы связаны с тренировками, питанием, прогрессом или абонементом.

## C11. Сложный сценарий: полный путь клиента за день

Цель: проверить основную ежедневную работу клиента.

Шаги:

1. Войти как `client1`.
2. Открыть **Питание**.
3. Добавить продукт в завтрак.
4. Открыть **Кабинет**.
5. Открыть текущий тренировочный план.
6. Нажать **Выполнить** у тренировочного дня.
7. Сохранить тренировку.
8. Открыть **Прогресс**.
9. Добавить новый вес и замеры.
10. Открыть **ИИ-рекомендации**.

Ожидаемый результат:

- питание сохраняется;
- тренировка сохраняется;
- прогресс сохраняется;
- графики и рекомендации обновляются;
- клиент может пройти полный пользовательский путь без ошибок.

## C12. Сложный сценарий: проверка защиты чужих данных

Цель: убедиться, что клиент не видит чужие карточки.

Шаги:

1. Войти как `client1`.
2. Открыть свою карточку через **Профиль**.
3. В адресной строке браузера попробовать изменить номер клиента, например с `/clients/1/` на `/clients/2/`.
4. Нажать Enter.

Ожидаемый результат:

- система запрещает доступ;
- чужой профиль не открывается.

# 4. Комплексные сценарии для демонстрации на защите

Эти сценарии лучше показывать преподавателю, потому что они демонстрируют пользу системы для бизнеса.

## D1. Полный цикл сопровождения клиента

Участники: администратор, тренер, клиент.

Шаги:

1. Администратор создает нового клиента.
2. Администратор назначает клиенту тренера.
3. Администратор оформляет абонемент.
4. Тренер входит в систему.
5. Тренер открывает карточку клиента.
6. Тренер создает тренировочный план.
7. Тренер задает норму питания.
8. Клиент входит в систему.
9. Клиент открывает план и выполняет тренировку.
10. Клиент добавляет питание.
11. Клиент добавляет прогресс.
12. Тренер снова открывает карточку клиента.
13. Тренер смотрит историю, прогресс и ИИ-рекомендации.
14. Тренер оставляет комментарий.

Ожидаемый результат:

- все участники выполняют свои задачи;
- данные сохраняются;
- каждый видит только свои разделы;
- система помогает сопровождать клиента от регистрации до анализа результата.

## D2. Сценарий удержания клиента

Участники: администратор или руководитель.

Шаги:

1. Администратор входит в систему.
2. Открывает **Дашборды**.
3. Смотрит показатель **Клиентов в зоне риска**.
4. Открывает блок **Клиенты для контакта**.
5. Нажимает **Открыть список**.
6. Открывает карточку клиента из списка.
7. Проверяет абонемент, последнюю тренировку и ИИ-рекомендации.

Ожидаемый результат:

- администратор понимает, почему клиент в зоне риска;
- система помогает принять бизнес-решение: позвонить клиенту, продлить абонемент или подключить тренера.

## D3. Сценарий анализа эффективности тренеров

Участники: администратор или руководитель.

Шаги:

1. Войти как администратор.
2. Открыть **Дашборды**.
3. Найти график **Загрузка тренеров**.
4. Открыть **Отчеты**.
5. Найти блок **Загрузка тренеров**.
6. Сравнить количество клиентов, активных клиентов и клиентов с низкой активностью.

Ожидаемый результат:

- руководитель видит нагрузку тренеров;
- можно понять, у кого много клиентов, а у кого клиенты менее активны.

# 5. Что обязательно проверить перед показом

Короткий чек-лист:

- вход работает для администратора, тренера и клиента;
- администратор видит клиентов, тренеров, дашборды и отчеты;
- тренер видит только своих клиентов;
- клиент видит только свои данные;
- можно создать клиента;
- можно оформить абонемент;
- можно создать тренировочный план;
- клиент может выполнить тренировку;
- клиент может добавить питание;
- клиент может добавить прогресс;
- графики отображаются;
- ИИ-рекомендации открываются;
- фильтр **Низкая активность** работает без ошибки;
- чужая карточка клиента не открывается обычному клиенту.
